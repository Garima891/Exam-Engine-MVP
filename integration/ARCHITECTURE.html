Architecture Overview

This report describes the implementation found in the repository. The Tkinter application owns student registration and a separate registered-student workflow. Registration captures face frames and a voice embedding. The live monitor uses a unique exam session, one CameraManager, a YOLO phone adapter, a MediaPipe/SFace identity adapter, and an isolated audio worker.

Security and Candidate Isolation

  • load_candidate_read_only() reads rows only for the supplied candidate_id.
  • Student flags require three face rows and one voice row for live start.
  • The live process receives the selected candidate's three face references and linked voice embedding.
  • No enroll.wav is the default database voice reference. An explicit WAV reference is optional and requires a matching candidate ID.
  • Voice/face blobs are protected with Windows DPAPI in the current storage implementation.
  • Captured frames and raw microphone recordings are not written to disk by the live monitor paths.
